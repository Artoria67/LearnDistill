# 提炼与编写标准

## 根据学习目的取舍

- 初学：保留最少的必要前置知识，定义后立即解释含义，再给短例子和检验题。
- 复习：突出概念关系、适用条件、公式选择和易混点，减少已掌握的展开。
- 题解：题目原文 → 思路 → 关键推导 → 结果 → 检验或易错点，步骤多少随难度和用户要求调整。

不要把“压缩为几页”当成用户一定能在某个时间内学会。阅读、思考和练习都占预算；给出可调整的时间分配，注明属于估计。预算明显不够时，标出核心内容和可选延伸，并取得用户对实质性范围取舍的选择。

## 内容要求

- 开头简短说明：资料范围、对应原文位置、目标语言、预计学习时长和会影响理解的假设/缺项。没有缺项就不强行写免责声明。
- 按原文章节或题号组织，保留原文标题。额外的小标题可自己拟定，但不能替换原文标识。
- 结论应带必要条件：例如分母非零、定义域、定理前提、参数范围、适用模型和单位。定义的量和公式中的符号要一致。
- 表格用于比较或对应，图用于解释关系；不把本可一句话说明的内容装饰成复杂图。
- 与当前任务有关的公式、图、表需要保留。补充推导、例子和图表有助于理解时才添加，并标明补充性质。
- 不添加来源没有支持的考试频率、重要性排名、“必考”或能力保证。可以解释概念依赖和常见的逻辑错误，但不要伪称统计结论。
- 用简短自检判断能否应用，答案/提示另放。用户只要速查表时不强加练习。

## Markdown 约定

- UTF-8，标准标题/列表/表格。显示公式使用 `$$ ... $$`，行内公式使用 `$ ... $`，也支持 `\[ ... \]` 和 `\( ... \)`。
- 图片使用相对路径，例如 `![图1 函数关系](assets/function.svg)`；原图编号和说明用普通可读文字保留。
- 不嵌入可执行 HTML，不使用在线字体/CDN。Mermaid 等代码块先导出 SVG/PNG，再以图片方式插入。
- 长表拆成能在纸面读清的几张；很宽的公式分行；长代码保留可阅读缩进并避免横向裁切。
- 来源写成可回查的文件名、页码、章节、题号或链接。文件内部不写宿主的工具引用 token。

结构按实际材料调整。不要为每份资料都生成不需要的封面、目录、术语表或大段学习方法建议。
