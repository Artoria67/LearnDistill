# 转换与交付

## 本地转换

在 skill 目录完成获准的依赖安装后，从任意工作目录运行：

```text
node <skill-dir>/scripts/render_pdf.mjs <notes.md> --output <notes.pdf> --html <notes.html> --title <title> --lang zh-CN
```

包含空格的路径和标题要使用当前 shell 的正确引号。不要通过拼接 shell 命令传入用户原文。

- 不指定输出路径时，在 Markdown 旁生成同名 `.pdf` 和 `.html`。
- `--browser <path>` 指定 Chromium/Edge/Chrome 的可执行文件；默认自动查找本机或 Playwright 已有浏览器。
- HTML 内嵌打印样式、KaTeX 字体和本地图片，预览与导出均不依赖网络。Markdown 源文件仍通过相对路径引用图片，需要连素材一并交付。
- 不支持远程图片 URL、越出 Markdown 所在目录的图片、可执行 SVG/HTML 或未展开的图表代码。先将已获准的素材复制/导出到 Markdown 旁的 `assets/` 中。
- 无效公式、缺失图片、明显横向溢出、浏览器启动失败会报错；修正源文件再重跑。生成失败时不把旧 PDF 当作新结果交付。

## 最终 PDF 验收

1. 用 PDF 解析器或 `pdfinfo` 确认页数大于零、文件可打开；提取文字核对章节和关键内容。
2. 用可用的 `pdftoppm` 等工具将 PDF 各页转成图片。示例：`pdftoppm -scale-to 1500 -png <notes.pdf> <qa-dir>/page`。
3. 逐页查看最终页面，核对中文/目标语言字形、公式上下标、图表标注、表格边界、段落与页码。需要时放大检查复杂公式。
4. 修复内容或排版，重新导出并重新检查；每次以最终 Markdown 为准。

没有 PDF 渲染/视觉查看工具时，尝试当前环境中的其他方法；确实无法检查，明确说明未完成视觉验收，不宣称已通过。PDF 必须仍然生成且可解析，否则工作流未完成。

## 交付形态

至少提供 `.md` 和 `.pdf` 的可访问链接，并说明资料范围和预计学习时长。生成 HTML 时提供其链接，宿主支持时直接打开它；对话中也可显示一小段真实内容预览，不能只写“已整理”。

Markdown 引用了图片时，同时提供素材目录或包含 Markdown 和素材的 ZIP，保持相对路径不变。不要仅交一个引用了本机临时图片、用户下载后失效的 Markdown。HTML/PDF 已内嵌图片也不能取代源文件的素材交付。

默认交付简洁成品，不附环境报告、调试日志和 PDF 验收截图。把未提供的材料和没有核实的内容写清楚；只在原资料确实残缺时，随后询问用户是否需要补全整理。
